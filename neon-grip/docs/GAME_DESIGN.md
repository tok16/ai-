# Neon Grip: Протокол «Хват» — GDD (конспект реализации)

Top-Down Twin-Stick Shooter · Bullet-Hell · Roguelite · Киберпанк-серверные фермы.
Строго **landscape**. Сбежавший боевой андроид прорывается через дата-центры мегакорпораций.

## 1. Философия 3 пальцев (эргономика)

| Палец | Зона | Роль | Реализация |
|---|---|---|---|
| Большой ЛЕВОЙ | левая половина экрана | Плавающий стик движения, 8 направлений | `ThreeFingerGripController` — стик рождается под первым касанием; снап к октантам (эмуляция D-pad) |
| Большой ПРАВОЙ | правый нижний квадрант | Стиль прицела + автоогонь | отклонил стик → стрельба началась; отпустил → бежит без огня |
| Указательный ПРАВОЙ | верхняя правая грань («триггер») | Рывок / ульта / перезарядка | короткий тап = рывок; удержание ≥600мс = перезарядка; зона сдвинута на ~12% внутрь экрана (dead-zone inset против соскальзывания на чехол) |

Каждый палец отслеживается по уникальному `pointerId`: отпускание одного не сбрасывает
другие (см. `touchUp`). Мультитач не конфликтует с системными свайпами за счёт
Immersive sticky mode (`NeonGripActivity`).

## 2. Механики Game Feel

* **Фазовый Сдвиг (рывок)** — `PlayerControlSystem`: импульс + 0.5 сек i-frames
  (`PhaseShift.invulnRemaining`). Если в i-frames пересекается вражеская пуля
  (`CollisionSystem`) → `AdrenalineRunner`: bullet-time 2 сек (таймскейл мира 0.35x
  в `GameWorld.update`) + homing-огонь на уязвимые точки.
* **Тактическая перезарядка** — двойной тап по правому стику ИЛИ долгое удержание
  триггера; выполняется корутиной `delay(1.4s)` — ритм боя важнее спама.
* **Комбо «Нейросеть»** — убийства копят шкалу Синхронизации (`GameState.addKill`),
  урон обнуляет её. При полной шкале следующий рывок оставляет взрывную волну /
  гравитационную мину (`consumeSync()` → `spawnSyncFinisher`).
* **Отдача** — экран НЕ трясётся (укачивание); дуло «отскакивает» (`recoilOffset`),
  гильзы/дым — из пула частиц.

## 3. Враги (заставляют использовать триггер)

|archetype|Паттерн|Контр-действие|
|---|---|---|
| Дрон-камикадзе | телеграф 0.5с → прямая гиператака 1400u/s | рывок вбок в последнюю долю секунды |
| Турель-предиктор | красный лазер в точку, где игрок будет через 1с | «сломать» паттерн движения рывком |
| Щитоносец (Фаланга) | фронтальный щит 140° блокирует пули | рывок за спину, продолжая стрелять |
| Снайпер | луч со «слепой зоной» 90px в центре | пересечь луч рывком |

Стейтмашины — линейные корутины (`ai/EnemyBrains.kt`): `delay → fire → teleport`,
без коллбэк-лапши. Смерть врага = `job.cancel()`.

### Crossfire: боты убивают друг друга и игрока

На арене всегда ДВА отряда корпоративной охраны — Alpha (`Faction.HOSTILE`)
и Bravo (`Faction.HOSTILE_B`). Они враждебны и игроку, и ДРУГ ДРУГУ (локальный
конфликт юрисдикций серверной фермы). Правила задаёт `Faction.isHostileTo`
(покрытие — `FactionHostilityTest`):

* **TargetingSystem** — каждый бот выбирает цель: игрок в приоритете (ANTIPLAYER),
  но если он «растворился» в Фазовом Сдвиге (i-frames) или вне радиуса — цель
  переключается на конкурента. Мёртвая цель сбрасывается мгновенно.
* **BotLocomotionSystem** — отряды входят с противоположных краёв и сходятся
  к центру: камикадзе таранят любого врага фракции (и бота тоже), фаланга
  наступает сквозь перестрелку, снайперы держат дистанцию, турели статичны.
* **BotCombatSystem** — упреждающие очереди по любой цели; детонация камикадзе
  наносит урон по площади ВСЕМ враждебным фракциям.
* **CollisionSystem** — HOSTILE-пуля Alpha долетает до Bravo и игрока;
  дружественный огонь внутри отряда выключен, поэтому волна не стирает себя сама.
* **GameState.crossfireKills** — счётчик чужих смертей на арене; комбо
  «Нейросеть» капается только за собственные убийства (`LastDamagedBy`).

Итог: один вовремя сделанный рывок превращает серверную ферму в хаос корпоративной
зачистки, где два отряда косят друг друга на глазах сбежавшего андроида.

## 4. Diegetic UI

* HP игрока: полоски нет — неоновый контур тускнеет и смещается синий→красный,
  персонаж искрит (<40% HP) — `NeonRenderSystem.blendNeon`.
* HP врагов: полоска над головой только 1 сек после попадания.
* Готовность триггера: пульсирующая неоновая полоска на верхней правой грани
  (зона указательного пальца, периферийное зрение).

## 5. Архитектура

```
core (:core, чистый Kotlin+LibGDX API)          android (:android)
├─ ecs/GameWorld.kt      Fleks-world, системы   ├─ NeonGripActivity.kt
├─ ecs/EntityFactory.kt  спавн в Safe Area      │   Immersive sticky, WindowInsets→SafeArea
├─ systems/*.kt          Control/Movement/AI/   └─ res/, manifest (sensorLandscape)
│                        Collision/Bullet/Fx/Render
├─ input/ThreeFingerGripController.kt
├─ ai/EnemyBrains.kt     корутина-стейтмашины
├─ pool/ObjectPool.kt    500 пуль ×2 фракции, 2000 частиц
├─ state/GameState.kt    StateFlow: sync/adrenaline/magazine/credits
├─ meta/NeuroTree.kt     ветки навыков Палец1/2/3
├─ meta/SpawnDirector.kt волны корутиной
└─ screens/              BunkerScreen (мета), RunScreen (забег)
```

Стек: **LibGDX 1.12.1** (OpenGL ES 3.0, 60/120 FPS) · **Fleks** (ECS на Kotlin) ·
**Coroutines/Flow** (AI-машинки, кулдауны, реактивный UI).

### Почему ECS
Пули/враги/частицы — тысячи объектов. ООП-иерархии дают полиморфные вызовы и
разброс по куче; Fleks хранит компоненты dense-массивами → последовательный проход
систем, cache-friendly, предсказуемый кадр.

### Object Pooling / батарея
`BulletSystem` держит два пула по 500 пуль, `FxParticlePoolSystem` — 2000 частиц.
В бою ноль аллокаций → нет микро-фризов GC → меньше нагрева SoC и экономия батареи.
Переполнение пула = пропуск выстрела/частицы, но не просадка кадра.

### Edge-to-Edge / Notch
Activity читает `WindowInsets`+`displayCutout` → `NeonGripGame.safeAreaFlow` (StateFlow) →
`EntityFactory.clampToSafeArea` сдвигает спавн и UI внутрь безопасной зоны.

## 6. Мета-прогрессия (Бункер)

Дерево «перепрошивки нейросети» привязано к пальцам (`meta/NeuroTree.kt`):
* **Палец 1 (Ноги)**: скорость, ядовитый след рывка, ледяная дорожка.
* **Палец 2 (Оружие)**: рикошет, дробление на 3, лазерный прицел weak-spot.
* **Палец 3 (Триггер)**: урон рывка сквозь врага, абордаж, гравитационные мины.
